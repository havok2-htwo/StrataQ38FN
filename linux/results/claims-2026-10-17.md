# Claim matrix for the planned write-up (2026-10-17)

Draft, read-only analysis. No GPU was used and no service was touched. Every number below was re-read from the raw rows
(`sweep.jsonl`, `agentic.jsonl`, `multiturn.jsonl`) or from the TESTLOG/analysis files named next to it.
Abbreviations: S = Strata 1441g (`strata-g3-1441f-lanes4`, `CMPV-1441g-text.json` = production minus vision),
MTP = vLLM 0.31 W4A16 with MTP (2 draft tokens, 8 seqs, 64K, `--max-num-batched-tokens 1024`),
noMTP = vLLM 0.31 W4A16 without MTP (64 seqs, 32K for the sweeps, 131K for agentic/multiturn).
One run per arm, no repeats. "agg" = aggregate output tok/s, "dec" = per-user decode tok/s p50.

Caveats that apply to every Strata-vs-vLLM ratio (from `cmp-2026-10-17.md`):
- different quantisations (S: unsloth UD-IQ4_XS GGUF; vLLM: W4A16 compressed-tensors) and K/V precision (S int8, vLLM bf16);
- the vLLM arms are **not stock vLLM 0.31**: the local sitecustomize `[ple-fp8 patch 0.31]` loads in every vLLM process;
- greedy replies match in 0 of the comparable pairs across engines (expected with different quants); quality is not compared.

## 2. Headline and outline the data supports today

**Headline (honest version):**
"On 4x RTX 3090, our Strata fork serves 16 users with a 262K context each and keeps agent conversations in a
128 GiB RAM / 600 GB SSD cache. It reaches 80-99 % of vLLM's raw throughput and finishes an agentic coding
benchmark 2.3x faster (119 s vs 271 s)."

**Outline (5-7 bullets):**
1. **Setup and fairness.** One host, both engines, same day, one run per arm. Different quantisations (IQ4_XS GGUF vs
   W4A16), int8 vs bf16 K/V, vLLM with a local PLE-fp8 patch. Throughput ratios compare engine + quant, not the engine alone.
2. **vs stock Strata (TESTLOG #76, 2026-10-14, older build of ours).** At 16 users +76 % short (516.7 vs 292.9 tok/s),
   +71 % at 1.2K, +65 % on 16 agents x 3 turns (follow-up TTFT 1.52 vs 9.91 s), byte-identical greedy output (82/82).
   Mainly 16 slots on a 4-card split instead of 8, plus admission costs (slot copy ~150 ms -> 1 ms). Mark it "to be
   re-measured with the current build" until the stock window has run.
3. **Raw throughput vs vLLM.** 1-4 users: 88-99 % of vLLM-with-MTP aggregate (both speculate; per-user decode 0.94-1.05x).
   8-16 users: 77-92 % (Strata has no speculation above 4 active requests). TTFT tails are worse on Strata under 16 users
   (p95 4.49 vs 0.81 s short).
4. **Context and memory.** 262,144 tokens per slot on all 16 slots (4.19 M tokens addressable, 458,752 resident in VRAM).
   vLLM's VRAM pool holds 76K-188K tokens in total with these configs. Strata's RAM tier holds ≈ 57 conversations of
   100K tokens (≈ 5.7 M tokens; pure-K/V bound 9-10 M), and the SSD tier ≈ 248 more (≈ 40 M tokens pure K/V).
   Present these as capacities computed from measured image sizes, not as a filled-cache benchmark.
5. **Agentic coding benchmark.** 118.9 s vs 271.2 s (vLLM no-MTP, 131K) vs 496.5 s (vLLM MTP, 64K/8 seqs), main-agent TTFT
   2.05 vs 12.74 vs 27.14 s, 71.8 vs 25.8 vs 17.3 tok/s. Multi-turn agents: 85.9 vs 266.6 s wall. The likely reason is
   capacity, not scheduling: 79 % of Strata's prompt tokens came from its caches, while vLLM's pool ran 97-100 % full.
6. **What our scheduler adds (vs stock Strata, not vs vLLM).** MTP speculation for up to 4 concurrent users (+26 to +45 %
   per-user decode at 2-4 users). Running replies keep decoding while a new prompt is read (pause 7.7 s -> 0.35 s),
   at the cost of +38 % TTFT for the joining request.
7. **Known limitation, stated openly.** Follow-up prompts queue behind one read pipe: today's multi-turn follow-up TTFT
   is 12.3 s (1.16 s on the pre-overlap build of 15.10). There is a fix in design. Strata does not read several prompts at once.

Phrases to avoid until the open items close: "much better than the original" without the build/date caveat,
"almost vLLM" (use the 77-99 % range), "multi prefill", "prefills never wait", "faster because of multi-user MTP /
multi decode", "full context" as a vLLM comparison without the vLLM 262K attempt.
