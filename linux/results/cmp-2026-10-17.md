**Draft, generated from raw files** (sweep.jsonl / agentic.jsonl / multiturn.jsonl rows, the .txt tables, server and
engine logs). Every ratio below was recomputed from the rows. One run per arm, no repeats, so expect a few % of noise.

Windows (production stopped in each): `window-cmp-vllm.sh` 09:40:51-09:53:18 (`cmpv-window.log`),
`window-agentic-cmp.sh` 09:54:26-10:12:40 (`cmpa-window.log`), `window-mtp-cmp.sh` 10:12:40-10:31:11 (`cmpm-window.log`).

Arms:
- **Strata**: engine `strata-g3-1441f-lanes4` (production binary), server `Strata-143-prod`, config
  `configs/CMPV-1441g-text.json`. This is production's `T16-1441g-lanes4-prod262r-vision-cpu.json` (= `production.json`,
  checked with diff) minus `--vision`, the `vision` section and `STRATA_MROPE_SLOTS`, with its own log and spill dir.
  Settings: 16 slots, `--max-context 262144`, `--kv-resident 28672`, spec lanes 4, solo pipeline, overlap
  (`STRATA_PIPE_OVERLAP(_KVS)`), plus the drop-in env `STRATA_ADMIT_SHORT_FIRST=8192 STRATA_PREFIX_DIAG=1`. Port 8095.
  **Strata also decodes speculatively with its MTP head in every run**: `--spec 4 --spec-min-p 0.5 --mtp
  Strata-data/mtp/rt`, the same as production. The engine log shows about 65 % of drafts accepted (spec lanes
  8,988 / 13,525 = 66.5 %, solo requests 2,047 / 3,212 = 63.7 %). Speculation only runs while 1-4 requests are active
  (solo pipeline plus spec lanes on slots 0/4/8/12, TESTLOG #82-#84). At 5 or more active requests Strata uses the
  batch path, which has no speculation (batch-MTP is still on the backlog).
- **vLLM-noMTP**: `VnimanieAI/Qwen3.8-Flash-Next-W4A16`, TP=4 + expert parallel, `max_num_seqs` 64, gpu util 0.94, prefix
  cache on. `--max-model-len` 32768 for the short/1.2K runs, 131072 for agentic/multiturn. `--max-num-batched-tokens` is
  not set, so vLLM uses its default.
- **vLLM-MTP**: same model, MTP `num_speculative_tokens` 2, `max_num_seqs` 8, `--max-num-batched-tokens 1024` (log:
  "Chunked prefill is enabled with max_num_batched_tokens=1024"; **only this arm**), gpu util 0.93, expert parallel,
  `--max-model-len` 65536 (every MTP number in this file).

Comparing like with like:
- **Speculation.** At 1-4 users both Strata and vLLM-MTP speculate, so S/MTP is the like-for-like decode comparison
  there. S/noMTP at 1-4 users compares speculative with non-speculative decoding, so it mixes the engine and MTP. Most
  of the 1.65x / 1.70x at 1 user comes from MTP, not from the engine. At 8 users vLLM-MTP still speculates and Strata
  does not, so S/MTP at 8 users is non-speculative vs speculative. At 8 and 16 users, S/noMTP compares two
  non-speculative arms.
- **Precision and build.** The quantisations differ: Strata uses the unsloth UD-IQ4_XS GGUF, vLLM uses W4A16
  compressed-tensors. Strata keeps K/V in int8 (`--kv int8`), while vLLM keeps it in bf16 (`kv_cache_dtype=auto`,
  `dtype=torch.bfloat16`). The vLLM arms are **not stock vLLM 0.31**: every vLLM server log (`cmpv-nomtp-`,
  `cmpa-nomtp-`, `cmpm-mtp64k-server.log`) shows the local sitecustomize patch loading in each process, `[ple-fp8 patch
  0.31] FP8 PLE method + exact host pinning + byte-wise pinned lookup`, which keeps the PLE table in FP8 in pinned host
  RAM. All three affect speed, KV capacity and quality. So every throughput ratio here compares engine and
  quantisation together, not the engine alone.

Units: "agg" means aggregate output tok/s. "dec p50" means per-user decode tok/s (median over requests). TTFT is in
seconds. In the ratios, S means Strata. A ratio above 1 means Strata is higher: better for tok/s, worse for TTFT.

## Notes and oddities

- **Strata multiturn follow-up TTFT regressed: 12.28 s today vs 1.16 s on 15.10**, at the same cached share (73 % / 79 %).
  The engine log (`Strata/strata-cmpv-1441g.log`, second `engine started` at 09:54:43) shows every follow-up read of
  ~4.1-4.2K new tokens as an *overlapped read* of 1.08-1.19 s ("the slots decoded 209-309 rows meanwhile"). The reads
  run one after another, so 16 near-simultaneous follow-ups queue: the server log shows "reading the prompt: ... 10-24 s
  so far" for 15K-20K-token prompts. The 15.10 reference ran on the pre-overlap production build (before #81 and
  #82-#84). Turn-1 decode p50 rose 9.6 -> 41.4 tok/s, so decode keeps running during reads. This is the trade-off that
  #80/#81 measured as "join TTFT x1.38", but here it is about 10x on follow-ups. It needs a dedicated A/B (overlap
  on/off, lanes on/off) before anyone quotes Strata's agent latency. The agentic sub/chat TTFT (1.08 -> 2.70 s,
  0.56 -> 1.74 s) points the same way. The 15.10 run was also on live production (:8090), and today's run used an
  isolated port, right after bench_agentic on the same server.
- vLLM-MTP at 1.2K x 8 users: agg 237.4 is *below* its own 4-user value (298.7). The 64K/8-seq KV pool (76K tokens) was
  98 % full. One request of user 7 waited 14.8 s for its first token and one of user 6 waited 10.8 s
  (`sweep.requests.jsonl`), and the log shows "Running: 7 reqs, Waiting: 1". Wall 34.5 s against a steady window of
  13.6 s. This arm also capped prefill at 1,024 tokens per step, so the 8 x 1.2K prompts needed about 10 prefill steps,
  and those steps shared the batch with decoding. That cap probably adds to the TTFT tail as well.
- vLLM-MTP agentic/multiturn are effectively serialised: 76K KV tokens hold about one 40-60K main prompt, so sub-agents
  and chat sit in the queue (TTFT 21-25 s p50). Its main-agent decode (136.4 tok/s) is high because the main agent often
  runs alone. A second limit applies to this arm only: `--max-num-batched-tokens 1024` caps chunked prefill at 1,024
  tokens per step, while noMTP ran with vLLM's default. A 37-63K-token main prompt therefore takes about 37-63 prefill
  steps, so this setting alone holds the TTFT back. Two settings drive the MTP vs noMTP TTFT gap (21-100 s), the
  KV pool and the prefill chunk size, and this run does not separate them. The arm's agentic/multiturn numbers are
  limited by its config. They describe MTP *at 64K, 8 seqs, 1K prefill chunk on 4x24 GB*, not MTP in general.
- vLLM prefix caching was active although the bench reports 0 cached: the logged running prefix-cache hit rate reached
  55.7 % in noMTP agentic, 39.1 % after noMTP multiturn, and 16.9 % / 11.8 % in the MTP runs (cumulative over the server's
  life, so the MTP figure includes the cache-free sweep phase). The high vLLM follow-up TTFTs are therefore not "no prefix
  cache". They also fit the KV pool being too small for 16 x 11-20K conversations (KV 97-100 %, waiting up to 13).
- The bench_agentic chat request count differs per arm (4/5/7/10) because the chat user posts every ~25 s for the whole
  wall time. Output totals therefore differ (6,998-8,585), so compare agg tok/s and wall with that in mind. vLLM-MTP also
  lost one main step (the 400).
- Strata 16 users short agg 516.7 equals TESTLOG #76's `cb144-ours-short` (516.7) by coincidence. These are different
  runs: 09:44:06 today vs 2026-10-14 04:15:16, TTFT p50 0.36 vs 0.89, steady 588.3 vs 548.9, other engine (g3-1441f-lanes4
  vs g3-143v2).
- Warm-up: the short runs use bench_concurrency's default single warm-up request in all three arms. The 1.2K runs use
  `--warmup 0` in all arms; Strata's long run attached to the already-warm short-run server. Strata's agentic run
  started ~2 min after a fresh engine start (09:56:42 ready), and multiturn followed on the same server.
- Strata's server log prints `"parallel": 16 - the engine runs at most 8 requests together; it will use 8`. This is a
  stale server message (`Strata-143-prod/serve/server.py:2894`, `PARALLEL_MAX = 8`). The server still passes
  `--batch 16`, and the engine reports 16 slot sessions per card and uses slots 10-15. No real limit; the text is
  misleading.
- Errors: none in any Strata run or vLLM-noMTP run. The only vLLM-MTP error is the one 400 above. No timeouts: every
  bench step reports rc 0, and the windows finished within their `timeout` limits.
- **Reply identity across engines is NOT expected and is not claimed.** The engines run different quantisations
  (Strata: unsloth UD-IQ4_XS GGUF; vLLM: W4A16 compressed-tensors). Greedy reply sha256s on identical requests (same
  prompt token counts) match in **0** of the comparable pairs: Strata vs noMTP 0/2, 0/4, 0/6, 0/8, 0/16, 0/32 (short) and
  0/2, 0/8, 0/32 (long); Strata vs MTP 0/2 ... 0/16; and also vLLM-noMTP vs vLLM-MTP 0/n at every level. Within Strata,
  exactness is covered by TESTLOG #76-#85, not by this window.
- Hardware: GPU means in `cmpv-strata-short.txt`/`long.txt` are 286-323 W, 52-68 % utilisation for Strata. No GPU sampling
  for the vLLM arms.
