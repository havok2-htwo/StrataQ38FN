Order from the critique
- A2 (chain rule drops every conversation sharing the system prompt root under STRATA_SLOT_CKPT_MOVE): stage 1 does
  NOT cover it (it never touches drop_superseded).  Fixed by STRATA_SUPERSEDE_PREFIX=1 (implied by SLOT_PARK): an entry
  is superseded when its live tokens start the outgoing ones, or when its deepest checkpoint does and is deeper than the
  outgoing chain's shallowest; pinned entries never.  Unit-tested only (no runtime test with a shared >= 2048-token
  system prompt was run; the kvaudit bench has 0 supersede events in both arms - every follow-up takes its image out).
- A1 (stale retained K/V after a slot give-back): stage 1 covers it with PARK_ASYNC; SLOT_PARK now drops it there too.
- The previous agent's WIP (stash) had: the prefix rule + its unit tests, the env stubs, StageQueueThreads and an
  unused BSlot::parks.  Kept and built on; the stub comments were rewritten for the final design.

What 2a does (generate.cpp)
- BDONE of a pipelined slot (pump): if it may be cached, its capture starts on StageQueueThreads (one thread per stage
  device, own 2 x 16 MiB pinned staging per device = 128 MiB), live = slot ids, running state + K/V [0,len), no draft
  layer, device_sync=false (each stage's batch_poll saw the window's streams idle).  RAM admission without evicting.
- Group start: a group whose window (own width, or the overlap's padded width) would pad-row an idle slot whose capture
  is still running is skipped; other groups go first.  Measured: 24x4: 62 waits, 0.83 s of one group's time / 156 s.
- Put into the cache (lazy checkpoint attach): when the slot is overwritten (BADM, before copy_to_slot) or, after a pad
  row wrote it, at the next request start (before best(), so that request can restore it).  Only then the slot's own
  checkpoints (the turn checkpoint, marked slot_turn) and the chain copies go into the image (split per stage).  While
  the slot still holds it, the slot is the source; a give-back from it (or a lent checkpoint mount) drops the image and
  the chain comes back into the main chain.
- The main sessions' copy of an admission's prompt is not parked ("N tokens not parked here: slot b parks them"); the
  chain it was read with (complete checkpoints of `checks`, not slot_turn ones) is copied for the slot on the park
  threads after BADM (AsyncPark with slot >= 0, host memory only), or synchronously at the next request when that could
  not run.  slot_turn keeps old turn checkpoints from riding along into every later image.
- Restore: draftless images are validated/restored with draft = nullptr; STRATA_SNAPSHOT_VERIFY skips the draft check.
- STRATA_SLOT_PARK_VERIFY=1: every slot capture compared with a plain capture of the same slot before anything writes it.
  STRATA_SLOT_PARK_TEST_RESTORE=1 (tests): every idle slot's image goes to the cache at the next request, so later
  turns are restored from slot images instead of the slot's give-back.
- Off (no env): byte-identical outputs (bt16-off, il-off == stage-1 reference dumps).

Open / next
- Capture is host-bound (fresh zero-filled pages, critique A3): ~44 ms per 367 MB slot capture, ~22 ms per 122 MB.
  A segment pool / no zero-fill / MADV_HUGEPAGE would shrink both stage 1 and 2a captures and the group waits.
- Prefix rule, conservative miss: an outgoing image whose only checkpoint is a deep turn checkpoint does not drop the
  same conversation's earlier copy when that copy's live tokens do not match (thinking-stripping clients) - left to LRU.
- A2 at runtime (shared system prompt >= 2048 tokens) not measured.  2b (server slot affinity) and 3a (SSD) not started.
